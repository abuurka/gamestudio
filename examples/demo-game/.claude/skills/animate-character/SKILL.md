# Animate a character or a prop

Clips are generated by code, so there is nothing to keyframe by hand. Every clip is a Blender action named after the clip, stored on its own NLA track, and exported as a separately named animation. The game plays it by name.

## 1. Make the character

```json
create_from_kit {"kind": "character_rigged", "params": {"name": "Hero", "height": 1.8, "color": "#3F7FD9"},
                 "location": [0, 0, 0], "collection": "Actors"}
```

This builds **two objects** (pass the name in `params`, so both get it):

- `Hero` is the armature and the **root**. It sits at the location with its origin at the feet and faces −Y. Components go on it. Results report its `dimensions` as the size of the mesh under it (`dimensions_from: "children"`), and `snap_to_ground` and `render_views` use that mesh.
- `Hero_Mesh` is the skinned mesh, a child of the armature. Leave it alone.

Bones: root, hips, spine, chest, neck, head, `upper_arm_L`/`lower_arm_L`, `upper_leg_L`/`lower_leg_L`, `foot_L` and the `_R` side (L is the character's left, +X).

Shape it with the `height`, `girth`, `head`, `legs`, `arms`, `hair` and colour params (`list_kits {"kind": "character_rigged"}` has the ranges). `regenerate_kit` works on either object: it rebuilds the mesh and bones and re-bakes every generated clip for the new proportions. Pass `clips: false` for a character with no clips.

It comes with these clips, all in place (the clips never move the armature object; the game moves the character):

| Clip | Loops | Length | Notes |
|---|---|---|---|
| `Idle` | yes | 4 s | Breathing, weight shift, a glance. The feet stay planted. |
| `Walk` | yes | about 0.8 s | The feet match **1.5 m/s** (`speed` param). |
| `Run` | yes | about 0.5 s | The feet match **4 m/s**. It has flight phases and pumping arms. |
| `Jump` | no | 1.25 s | A whole jump: crouch, take off, tuck, land, stand. |
| `JumpStart` | no | 0.42 s | Crouch and push off. Ends in the `JumpAir` pose. |
| `JumpAir` | yes | 1 s | In the air. |
| `Land` | no | 0.5 s | From `JumpAir`: impact crouch, then stand. |
| `Wave` | yes | 1.2 s | The right hand waves above the shoulder. |
| `Fall` | yes | 0.8 s | Flailing in the air, looking down. |

## 2. Tune clips or add more (`run_python`)

```python
hero = D.objects["Hero"]
anim = gs.kits.animation
anim.add_clip(hero, "walk", {"speed": 2.0, "stride": 1.1, "bounce": 0.6})   # re-keys Walk for 2 m/s
anim.add_clip(hero, "run", {"speed": 5.0})                                  # match CharacterController.speed
anim.add_clip(hero, "wave", {"arm": "left"}, name="WaveLeft")               # an extra clip
result = anim.clips(hero)   # [{name, loop, seconds, frames, ground_speed, params, ...}]
```

- **Kinds:** `idle`, `walk`, `run`, `jump`, `jump_start`, `jump_air`, `land`, `wave`, `fall`. Clip names such as `"JumpAir"` work too. `anim.catalog()` lists every kind with its params schema.
- **Walk and run:** `speed` is the ground speed in m/s that the planted feet match. Set it to the `CharacterController.speed`, or play the clip at `speed = controller speed / clip ground_speed`. Otherwise the feet slide. `stride` lengthens the steps, and `bounce` scales the hip bob (0 keeps the hips level).
- **The other clips:** `speed` is the tempo (2 = twice as fast), `stride` the size of the arm and limb motion, and `bounce` the crouch or bob depth.
- Calling `add_clip` again with the same kind and name re-keys that clip. `anim.remove_clip(hero, "WaveLeft")` deletes one. `anim.preview(hero, "Walk", frame=8)` makes it the active action and goes to that frame, so you can look at a pose with `render_views`.

## 3. Animate props (any object)

Small loops make a level feel alive: pickups that spin and bob, trees that sway, doors that open.

```python
anim = gs.kits.animation
for n in ["Coin_01", "Coin_02", "Coin_03"]:
    anim.add_clip(D.objects[n], ["spin", "bob"], {"spin": {"speed": 0.5}, "bob": {"height": 0.2}})  # one clip "spin_bob"
anim.add_clip(D.objects["Door"], "door_open", {"angle": 100, "seconds": 0.8})
anim.add_clip(D.objects["Oak"], "sway", {"angle": 4})
anim.add_clip(D.objects["Platform"], "hover", {"height": 0.3})
```

| Kind | Loops | What it keys |
|---|---|---|
| `spin` | yes | Rotation about an axis through the origin, one turn per loop (`speed` in turns per second) |
| `bob` | yes | Location: up and down around its place |
| `pulse` | yes | Scale |
| `sway` | yes | A tilt about the origin (trees: their origin is at the base) |
| `hover` | yes | Drifts up and down and rocks |
| `door_open` / `door_close` | no | Rotation about the object's own Z through its origin. Put the origin on the hinge. A negative `angle` swings the other way (the right leaf of a double gate). |

- Looping clips play in the game with `add_component {"objects": [...], "component": "Animator"}`: an empty `clip` plays the first clip on the object. One-shot clips (`door_open`) are played from code (section 4).
- These clips key the object's own transform around **where it is now**. Place the object first. If you move it later, call `add_clip` again.
- Identical clips share one action. Ten coins with the same `spin_bob` use one action, and the export has one animation.
- A clip overrides gameplay movement of the object it keys. If code moves the object, animate a child instead. **Prefabs:** never animate the prefab's root. Animate a child, for example `CoinRoot` (moved by code, `Spin` component) > `CoinBody` (`bob` clip).
- The same goes for a playtest's `start`: it cannot move an object whose clip keys its location (a bobbing key snaps back).
- A collider does not follow a clip. When a door opens, drop its collider in code: `door.remove(Collider)` (import `Collider` from `@gamestudio/engine`).
- The built-in `Spin` component also turns things, from code, at any speed. Use a clip when the motion should be authored or combined with other motion.

## 4. Play clips in the game

- **Characters: an animation graph** (prefer it for any player, enemy or NPC with more than a clip or two). A graph is a state machine in TypeScript: states play a clip or blend several by a parameter, and transitions fire on parameters, exit times or triggers. Gameplay code only sets parameters. Write it in `src/systems/` (imported by `main.ts`), then name it in an `Animator` on the **armature**: `add_component {"objects": "Hero", "component": "Animator", "values": {"graph": "Hero"}}`.

  ```ts
  // src/systems/hero-animation.ts
  import { defineAnimationGraph } from '@gamestudio/engine';

  export const HeroGraph = defineAnimationGraph('Hero', {
    parameters: {
      speed: { type: 'float', from: 'speed' },                  // horizontal m/s, measured
      vy: { type: 'float', from: 'verticalSpeed' },
      grounded: { type: 'bool', from: 'grounded', default: true },
      attack: { type: 'trigger', hold: 0.15 },                   // set by code
    },
    states: {
      Move: { blend: { by: 'speed', clips: [[0, 'Idle'], [1.5, 'Walk'], [4, 'Run']] } },
      Jump: { clip: 'JumpStart', loop: false, speed: 1.6, next: 'Air' },
      Air: { clip: 'JumpAir' },
      Land: { clip: 'Land', loop: false, speed: 1.5, next: 'Move' },
      Attack: { clip: 'Wave', loop: false, next: 'Move', events: { hit: 0.4 } },
    },
    transitions: [
      { from: ['Move', 'Land'], to: 'Jump', when: (p) => !p.grounded && p.vy > 0.5, blend: 0.05 },
      { from: ['Jump', 'Air'], to: 'Land', when: 'grounded', blend: 0.05 },
      { from: 'Move', to: 'Attack', when: 'attack', blend: 0.1 },
    ],
  });
  ```

  - Parameters with `from` (`speed`, `verticalSpeed`, `grounded`, `airTime`) fill themselves from the movement and the `CharacterController`, so a graph made only of them needs no code. Set the others from a system: `ctx.animation.graph(hero, HeroGraph)?.set('aiming', true)` or `.trigger('attack')` (typed with the graph object). Named `events` arrive in `ctx.animation.events` (`type: 'event'`), and so do `'enter'`/`'exit'` of each state.
  - Blend thresholds are values of the parameter: put the kit clips' ground speeds there (Walk 1.5, Run 4), and add `[6, 'Run', 1.5]` to play Run faster at 6 m/s.
  - `next` goes on once a clip has played; `exitTime` holds a transition back until then; `from: '*'` is any state. Mistakes (unknown state, parameter or a transition with neither `when` nor `exitTime`) throw when the game loads, with the names that exist, in `game_logs`.
  - The platformer template's `src/systems/player-animation.ts` is a complete example. API.md §15 has the reference.
- **Always the same clip:** `add_component {"objects": "Hero", "component": "Animator", "values": {"clip": "Idle"}}`. Put it on the **armature**, or on the prop that the clip animates. The fields are `clip`, `loop`, `speed`, `playOnStart`, `fade`, and `graph` (above).
- **From code:** `ctx.animation.play(entity, 'Walk', { fade: 0.15 })`. For one-shot clips (`Jump`, `JumpStart`, `Land`, `door_open`), pass `loop: false`. Their end shows up in `ctx.animation.events` as `{type: 'finished'}`. A second character's clips are `Walk.001` and so on in Blender, and `play(other, 'Walk')` still finds them.
- **NPCs:** `Animator` alone for idlers and wavers. A walker or chaser gets a small graph whose `Move` state blends Idle and Walk by `from: 'speed'`, so it animates however its system moves it.
- **The quickest player, with no code:** put the three player components and `Locomotion` on the armature:

  ```json
  add_component {"objects": "Hero", "components": {"RigidBody": {"type": "kinematic"}, "Collider": {"shape": "capsule"},
                                                   "CharacterController": {}, "Locomotion": {}}}
  ```

  The controller moves and turns the armature, and the bones follow. The capsule is sized from the skinned mesh in its rest pose, so the feet stand on the ground (2 cm skin, like the `character` kit). `Locomotion` plays `Idle`, `Walk`, `Run`, `Jump` and `Fall` from how the character moves (`walkSpeed`, `runSpeed`, `fade`; empty names are skipped), and `tracked.changes["Locomotion.clip"]` in a playtest shows which ran. Gameplay code finds the player the same way as before (`ctx.world.query(CharacterController)`), and the origin is still at the feet.
- **Custom gaits** (a `Land` after `JumpAir`, a dash, attacks): use a graph instead of `Locomotion`, and never both on one entity. `ctx.animation.play` on a graph-driven entity takes it over until `ctx.animation.graph(entity, 'Hero')` starts the graph again.
- **Attach something to a bone:** `ctx.animation.bone(hero, 'head')?.add(hat.object3d)` (a hat, a torch in `lower_arm_R`). Bone names are in section 1; it works on the armature entity and on its mesh.
- **Replacing the starter `Player`:** `delete_objects` it (the result lists `FollowCamera.target` under `cleared_references`), `create_from_kit` the rigged one with `params.name: "Player"`, add the components above (and your own, such as a round-state component), `set_transform {"name": "Player", "location": [x, y, 0], "rotation_deg": [0, 0, 180], "snap_to_ground": true}` to face away from the camera, then `set_component` the camera's `FollowCamera.target` back to `Player`.

## Verification gates

1. `list_clips {"objects": ["Hero"]}`. Every clip is listed, with no warnings about skipped tracks.
2. `render_views {"target": "Hero", "views": ["front", "side"]}`. For a pose, first `gs.kits.animation.preview(D.objects["Hero"], "Run", frame=5)` in `run_python`. The feet are on the ground, the hands clear of the body, and the character faces −Y.
3. `validate_assets {"names": ["Hero_Mesh"]}`. The only expected note is the Armature modifier info.
4. `playtest` with screenshots spread over a few seconds (it exports first). The character animates (compare two screenshots), and `game_logs` has no `[animation]` warnings. `list_clips` now shows the clips under `exported_clips`.
5. With a graph: the playtest's `changes["Animator.state"]` lists the states it went through (`count`, `first_s`, `last_s`), and `game_state` shows each animated entity's `animation` (`state`, `clip`, `params`). Drive inputs that should change state (a jump, a trigger) and check the state changed when expected.

## Common failures

| Symptom | Fix |
|---|---|
| `Clip "Walk" does not animate "Hero_Mesh"` | Put the `Animator`, or the `play()` call, on the armature `Hero`, not on the mesh. |
| The feet slide when the character moves | The clip's ground speed differs from `CharacterController.speed`. Re-key it with `add_clip(hero, "run", {"speed": <controller speed>})`. |
| The rigged player floats or sinks | The components are on `Hero_Mesh` instead of the armature `Hero`, or it started inside the ground: `snap_to_ground`. |
| The player slides in its `Idle` pose | `Locomotion` (or an `Animator` with a `graph`) is missing, or its clip names don't match the character's clips (`list_clips`). |
| `No animation graph "Hero"` | The graph's module is not imported (put it in `src/systems/`), or the name in `Animator.graph` differs from `defineAnimationGraph('Hero', ...)`. |
| A graph never leaves a state | Check `game_state` `animation.params`: a `from` parameter needs a `CharacterController` on the entity or an ancestor for `grounded`; a trigger nothing takes clears after one frame (give it `hold`). |
| The prop jumps back to an old spot | Its clip keys the location where it was. Call `add_clip` again after moving it, or animate a child. |
| `add_clip` says the object already has a clip of that name | A hand-made action uses that name. Pass `name="..."`. |
| A humanoid clip on another rig fails | Humanoid clips need a `character_rigged` armature. Other armatures need hand-made actions on NLA tracks (see `list_clips`). |
| The clip looks too fast or slow in Blender | The scene is not at 30 fps. The game uses seconds, so it is right there. |
